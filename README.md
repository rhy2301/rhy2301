## Highlights

**Reading the source instead of trusting the surface**

- Solscan shows activity labels as if they were on-chain facts. Checking against the data showed they are **generated by the indexer**, not stored on chain.
- I wanted to know whether you can tell which path a transaction came in through. In agave, the sender's socket address lives only in the in-memory `Packet.meta`, so **the entry path leaves no on-chain trace**.
- RPC `SendTransactionService` keeps pending transactions in a **HashMap with no priority ordering**. The validator's `ForwardingStage` sorts with a MinMaxHeap, and the leader's `BankingStage` **recomputes priority on its own anyway**.
- SWQoS looks like a protocol guarantee, but the trust between an RPC and a validator comes from a **stake-override setting agreed off-chain** — it's a social contract, not something the protocol enforces.

**Letting an LLM touch money safely** (TreAgent)

- The object that moves funds (`ExecutionIntent`) can only be created inside PolicyGuard, so **if an intent exists, it has passed every check**.
- Separated *clamp* from *reject*: an amount over the limit gets trimmed and still paid (half a payroll beats none), but an unknown wallet or broken schema throws out the whole plan.
- Kept devnet transfers and localnet x402 payments strictly apart, and **never generate an explorer link for a signature nobody can verify publicly**.
